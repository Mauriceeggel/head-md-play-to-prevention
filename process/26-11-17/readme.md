Token → Roughly speaking, how do robots process/interpret our language ?

Robots are "prediction machines" → they predict one token after another.

Robots will take into account every single detail of a sentence: the cat | the cat-alogue

[Attention is all you need](https://en.wikipedia.org/wiki/Attention_Is_All_You_Need) 

<u>**Semantic Territories**</u> →  Define the "terrain" of meaning (context)

Our greatest enemy when speaking to robots is being generic.<br>
What matters is not the prompt (prompt engineering), but rather the <u>context</u> (context engineering).

context engineering → the systematic practice of designing, structuring, and dynamically managing everything a Large Language Model (LLM) or AI agent sees inside its context window before it generates a response.

→ Information Environment [exemples, références, images, ...]

<u>**More context ≠ better results**</u>

<u>**Reverse engineer prompting:**</u>

If you achieve the desired result, it is important to ask the robot to summarize and provide the prompt that made this "perfect result" possible.
(The flipped interaction pattern)

→ As part of our project, every pitch we make can be considered a kind of iteration of a context for the robots.

Try to describe the experience that the game can create for the player.<br>
→ Helps in understanding our goal, as well as its ultimate outcome.

Critically evaluate all decisions/proposals put forward by the robots, in order to return to the most essential elements of the project.

For example, if a reference is provided, you must examine all aspects of that reference → such as why it is or is not relevant...
